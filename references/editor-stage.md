# 编辑与导出阶段（阶段 D / F）：与网页编辑器协作

> 读取时机：`set-stage editor` 放行后（阶段 D）；收到 `editing_done` 事件后做
> 终检与导出（阶段 F）。本文命令中的 `python` 是实际解释器绝对路径；Windows 可用 `scripts/run.ps1`，macOS 可用 `scripts/run.sh` 调用同名脚本。本文路径相对 skill 根目录，`<项目目录>` 指用途目录。

## 1. 网页编辑器能力（Agent 引导用户用，边界要讲准）

用户在浏览器里可以：

- 点击预览（真实 Typst 渲染的 SVG）中的**文字块**就地编辑字段；
- 结构面板**增删经历与 bullet**、同板块内**拖拽排序**（不做跨板块拖拽）；
- 每次保存自动重渲染并刷新页面；
- 顶栏**切换模板**（会回到生成等待页，触发 Agent 重新排版检查，见 rendering-stage.md §6）；
- **导出菜单 → 导出正式 PDF**；**完成**按钮通知 Agent 终检；
- 事实核对页（facts）只读展示 claim-map 四态与筛选。

没有 AI 对话按钮、没有历史快照。以上覆盖不了的修改，用户回到对话让 Agent 做。

## 2. Agent 侧协作（阶段 D 的对话继续可用）

- **Agent 仍是 resume.json 的合法写入方**：在对话里改措辞 / 调结构，直接写
  `<项目目录>/resume.json`（遵守 data-contract.md；校验失败不会破坏现有文件）。
  写盘后服务自动重渲染，浏览器自动刷新，无需通知用户刷新。
- **后保存者生效**：网页与 Agent 并发修改不做合并，谁的保存晚谁生效。因此
  **每次写之前先重读最新 resume.json**，基于最新内容改，避免覆盖用户刚在
  网页保存的修改；写入要快，改完立刻保存。
- **claim-map 分工**：网页只读；状态只由 Agent 在对话中维护；用户在网页改了
  措辞**不**自动改状态；claim 状态不阻止导出。涉及事实的修改（数字、头衔、
  时间）在对话里做时，同步更新 claim-map。
- 页数监控：编辑器显示实际页数；用户加内容导致超过 2 页时页面会提示，
  Agent 负责在终检时精简。

## 3. 等待完成与终检（阶段 F 入口）

```bash
python scripts/wait_for_event.py "<项目目录>" --timeout 60
```

- 等到 `editing_done`（用户点了「完成」）→ 读取最新 resume.json，按 rendering-stage.md §4 补查尚未检查的修改与受影响页面；当前版本已检查通过则直接进入导出。
- 终检通过 → 请用户在编辑器点**「导出 → 导出正式 PDF」**（导出由用户触发：
  服务会强制重编译当前 JSON 与模板，复制为规范文件名的 PDF，阶段转 done）。
- 终检发现问题 → 在对话里修 resume.json（服务自动重渲染），看过修改后的实际页面再请用户导出。
- 用户没点「完成」但直接点了导出：同样有效（导出事件 `exported` 落盘，阶段
  done）；Agent 在下轮对话里补做上述终检，发现问题则修正、复查后提醒用户重新导出。

导出文件名自动生成：`姓名-目标岗位-电话.pdf`（缺电话时 `姓名-目标岗位.pdf`，
非法字符替换为 `-`，规则见 data-contract.md §11）。中间文件留在
`work/build/`，不作为交付物。

## 4. 收尾与会话恢复

- 导出后**服务先别急着停**：用户常会再改几轮。用户明确表示完成，或长时间
  无操作后，停掉 serve 进程即可（Ctrl-C 或结束后台任务）。
- 用户中途关了浏览器 / 服务：无损——状态都在磁盘（resume.json / session.json /
  events.jsonl）。用户再次唤起 skill 时：
  1. `python scripts/session.py "<项目目录>" show` 看阶段；
  2. `writing` → 回 writing-stage.md；`gallery`/`generating` → template-selection.md
     §4 恢复；`editor`/`done` → 重启服务（serve.py 会恢复会话），按本文继续。
- `done` 之后用户又想改：直接重启服务进编辑器即可；内容变化大就当作新的
  编辑轮次（本文 §2–§3 再走一遍）。

## 5. 常见情况

| 现象 | 处理 |
|---|---|
| 等待页卡在"生成中" | 查看 `work/render-result.json`、`work/render-error.log` 和当前会话选择；先修具体错误再重试。JSON 仍为旧模板时先由 Agent 完成适配。 |
| 渲染失败 toast | 指引见 rendering-stage.md §7；对话里修 JSON 即触发自动重渲染 |
| 网页显示旧内容 | 查看页面连接提示与 `work/server.json`，用最新带令牌的链接重开。服务停止才重启；不要同时开两个服务。 |
| Agent 改了 JSON 网页没刷新 | 检查最近渲染结果与连接；文件监听每 0.4 秒、页面轮询默认每 1.2 秒。页面还会核对当前状态，可恢复漏掉的完成事件。 |
